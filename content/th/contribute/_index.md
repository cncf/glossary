## ยินดีต้อนรับ

ยินดีต้อนรับสู่คู่มือการมีส่วนร่วมในโครงการอภิธานศัพท์ Cloud Native

การมีส่วนร่วมในการพัฒนาโครงการนี้ สามารถทำได้หลายรูปแบบ ดังนี้

1) [การมีส่วนร่วมใน Issue ที่มีอยู่แล้ว](#work-on-an-existing-issue)
2) [การเสนอคำศัพท์ใหม่](#propose-new-terms)
3) [การแก้ไขคำศัพท์ที่มีอยู่แล้ว](#update-an-existing-term)

## ภาพรวมของโครงการ

เป้าหมายของโครงการนี้ คือการทำให้เทคโนโลยี Cloud Native ซึ่งมีความซับซ้อนและมีคำศัพท์เฉพาะทางค่อนข้างมาก กลายเป็นเรื่องที่เข้าใจง่าย เพื่อเปิดโอกาสให้ผู้ที่สนใจทุกคนเข้าถึงได้มากขึ้น

เนื้อหาของอภิธานศัพท์จะถูกจัดเก็บใน [GitHub นี้](https://github.com/cncf/glossary)
ซึ่งจะประกอบไปด้วย [Issue](https://github.com/cncf/glossary/issues)  [Pull Request](https://github.com/cncf/glossary/pulls) และ
[Discussion](https://github.com/cncf/glossary/discussions) เกี่ยวกับอภิธานศัพท์

## ใครสามารถมีส่วนร่วมได้บ้าง

รูปแบบการมีส่วนร่วมในโครงการนี้จะขึ้นอยู่กับระดับความเชี่ยวชาญด้าน Cloud Native ของแต่ละบุคคล เนื่องจากเนื้อหาในส่วนนี้มีความซับซ้อน การย่อยแนวคิดให้เข้าใจง่ายจึงจำเป็นต้องอาศัยความรู้ความเข้าใจที่ลึกซึ้ง
ดังนั้น ผู้ที่ต้องการเพิ่มหรือเขียนบทนิยามสำหรับคำศัพท์ใหม่ ควรมีความเชี่ยวชาญในเทคโนโลยีเหล่านั้นเป็นอย่างดี โดยทั่วไปแล้ว ผู้ร่วมจัดทำ (Contributors) มักจะเป็นวิศวกรผู้มีประสบการณ์ตรง หรือนักวิชาการที่ศึกษาเน้นหนักด้าน Cloud Native โดยเฉพาะ

ความรู้ดังกล่าวเป็นสิ่งจำเป็นมาก เพราะการอธิบายเรื่องยาก ๆ ด้วยคำง่าย ๆ เป็นเรื่องที่ ท้าทายอย่างยิ่ง
และแม้ผลลัพธ์ที่อ่านง่ายและเป็นมิตรต่อผู้ใช้จะดูเหมือนไม่มีอะไรซับซ้อน แต่ความเรียบง่ายที่ได้มาตรฐานนั้น เกิดจากการทำงานอย่างหนักและการร่วมมือกันของผู้เชี่ยวชาญด้าน Cloud Native

สำหรับผู้ที่ยังไม่มีความเชี่ยวชาญด้าน Cloud Native แต่ต้องการมีส่วนร่วมในโครงการ ขอแนะนำให้จับคู่ทำงานร่วมกับผู้เชี่ยวชาญ และเมื่อได้รับการยืนยันความถูกต้องแม่นยำของเนื้อหาแล้ว ก็พร้อมสำหรับการส่งผลงานชิ้นแรกเข้าสู่อภิธานศัพท์ได้ทันที

งานแปลภาษาถือเป็นจุดเริ่มต้นที่ดีสำหรับผู้มีความสามารถด้านภาษาในการสร้างคุณค่าให้อภิธานศัพท์นี้ เนื่องจากมีบทนิยามภาษาอังกฤษที่สมบูรณ์เป็นต้นแบบอยู่แล้ว

ผู้ร่วมจัดทำที่มีประสบการณ์น้อยสามารถเข้าร่วมแปลคำศัพท์เป็นภาษาปลายทางได้เช่นกัน โดยเลือกเข้าร่วมทีมแปลที่มีอยู่แล้วหรือจัดตั้งทีมใหม่ และศึกษาแนวทางการเริ่มต้นได้ที่หัวข้อ [การช่วยแปลอภิธานศัพท์เป็นภาษาท้องถิ่น](#help-localize-the-glossary) ในคู่มือฉบับนี้

## ก่อนเริ่มต้น

ก่อนเริ่มต้นการทำงานในฐานะผู้ร่วมจัดทำอภิธานศัพท์ โปรดดำเนินการตามขั้นตอนต่อไปนี้:

1. สร้าง [บัญชีผู้ใช้งานระบบ GitHub](https://docs.github.com/en/get-started/signing-up-for-github/signing-up-for-a-new-github-account) หากยังไม่มี
2. หากคุณกำลังทำงานบนระบบคอมพิวเตอร์ส่วนตัว
ตั้งค่า [ชื่อผู้ใช้งาน `user.name`](https://docs.github.com/en/get-started/git-basics/setting-your-username-in-git#setting-your-git-username-for-every-repository-on-your-computer) แล ะ[ที่อยู่อีเมล `user.email`](https://docs.github.com/en/account-and-profile/setting-up-and-managing-your-personal-account-on-github/managing-email-preferences/setting-your-commit-email-address#setting-your-email-address-for-every-repository-on-your-computer) ให้ถูกต้องในระบบ git
3. ทุกครั้งที่บันทึกการเปลี่ยนแปลงโค้ดด้วยคำสั่งบันทึก โดยใช้คำสั่ง `git commit`
ให้เพิ่มตัวเลือก `-s` ในคำสั่ง เพื่อเพิ่มลายเซ็นรับรองการเปิดเผยข้อมูลการพัฒนา (DCO signature)
หรือสามารถตั้งคำสั่งลัดในระบบตั้งค่า `gitconfig` เพื่อความสะดวกในการใช้งานครั้งต่อไปก็ได้ โดยใช้คำสั่ง `git config --global alias.ci "commit -s"`

## แนวทางปฏิบัติ {#best-practices}

เพื่อให้กระบวนการตรวจสอบราบรื่น โปรดใช้ [การขึ้นบรรทัดใหม่ตามความหมายของประโยค (semantic line breaks)](https://sembr.org)
แนะนำให้ศึกษาและอ้างอิงจาก [คู่มือสรุปการจัดรูปแบบข้อความมาร์กดาวน์ (markdown)](https://www.markdownguide.org/cheat-sheet/) นี้
เพื่อจัดรูปแบบข้อความบนระบบนี้ได้อย่างถูกต้อง เช่น การสร้างลิงก์เชื่อมโยง ข้อความตัวหนา ข้อความตัวเอียง และเมื่อตั้งชื่อไฟล์เอกสาร .md โปรดใช้ตัวพิมพ์เล็กทั้งหมดและใช้เครื่องหมายขีดกลางแทนการใช้ช่องว่างเพื่อคั่นคำ พร้อมทั้งหลีกเลี่ยงการใช้เครื่องหมายวงเล็บ

## คู่มือรูปแบบเอกสาร

อ่าน [คู่มือรูปแบบเอกสาร](/style-guide/) ของเราเพื่อทำความเข้าใจแนวทางในการจัดรูปแบบและเขียนเอกสาร และทำให้กระบวนการมีส่วนร่วมมีประสิทธิภาพมากขึ้น

## เข้าร่วมชุมชน {#join-the-glossary-community}

ผู้สนใจเข้าร่วมชุมชนสามารถติดต่อสื่อสารกับผู้ดูแลและผู้ร่วมจัดทำคนอื่น ๆ ได้ในช่องห้องสนทนา [#glossary](https://cloud-native.slack.com/archives/C02TX20MQBB) บน CNCF Slack

ทุกคนสามารถเข้าร่วมได้เลย พวกเรายินดีต้อนรับครับ/ค่ะ!

## การมีส่วนร่วมใน Issue ที่มีอยู่แล้ว {#work-on-an-existing-issue}

ผู้สนใจมีส่วนร่วมในหัวข้อ หรือ Issue ที่มีอยู่แล้วสามารถไปที่ [cncf/glossary GitHub Issue](https://github.com/cncf/glossary/issues) เพื่อดูรายการ Issue ที่มีอยู่
โดยสามารถใช้ป้ายกำกับ หรือ label เช่น English language, help needed, good first issue เพื่อกรอง Issue ที่สนใจได้

![Issue และ Label](/images/how-to/issue-and-labels.png)

ตรวจสอบให้แน่ใจว่าคำศัพท์ที่คุณเลือกยังไม่ได้ถูกมอบหมายให้ใครแล้ว
ตัวอย่างเช่น จากภาพนี้จะเห็นว่าคำสามคำแรกยังว่างอยู่ ส่วนคำที่สี่มีผู้จองไปแล้ว

![แสดงความติดเห็น](/images/how-to/howto-04.png)

เมื่อคุณเลือกคำศัพท์ที่จะแปล ให้แสดงความคิดเห็นในประเด็นนั้น

![จองคำศัพท์เพื่อจัดทำ](/images/how-to/claiming-an-issue.png)

นอกจากนี้ ควรแจ้งผู้ดูแลในช่อง [#glossary](https://cloud-native.slack.com/archives/C02TX20MQBB) ของ CNCF Slack workspace และระบุ (tag) ชื่อบัญชีผู้ใช้งานดังต่อไปนี้ _@iamnoah_, _@nate-double-u_, _@Seokho Son_, _@Jihoon Seo_ และ/หรือ _@Junya Okabe_ เพื่อให้มั่นใจว่าพวกเขาจะไม่พลาดการติดต่อของคุณ

สำหรับขั้นตอนถัดไป โปรดศึกษาเพิ่มเติมได้ที่หัวข้อ [การส่งคำศัพท์ใหม่ (การส่ง PR)](#submitting-a-new-term)

**หมายเหตุ**: คุณจะสามารถเริ่มทำงานใน Issue ดังกล่าวได้ หลังจากที่ผู้ดูแลระบบได้มอบหมายงานให้กับคุณอย่างเป็นทางการแล้วเท่านั้น และคุณสามารถเลือกจองเพื่อจัดทำคำศัพท์ได้เพียงครั้งละหนึ่งคำศัพท์เท่านั้น หากคุณต้องการทำงานกับคำศัพท์หลายคำเป็นลำดับขั้น คุณจำเป็นต้องจัดทำคำศัพท์แรกให้เสร็จสิ้นสมบูรณ์ก่อน จึงจะสามารถเลือกจองคำศัพท์ในลำดับถัดไปได้

## การเสนอคำศัพท์ใหม่ {#propose-new-terms}

หากต้องการเสนอคำศัพท์ฺใหม่เพื่อให้ผู้อื่นนำไปจัดทำ หรือจะจัดทำด้วยตนเอง
สามารถเริ่มต้นด้วย [การสร้าง Issue ใหม่](#creating-an-issue)
เพื่อให้เพิ่มเข้าในอภิธานศัพท์ได้ คำศัพท์ใหม่ทุกคำต้องจะต้องสอดคล้องกับ [คำนิยาม Cloud Native ของ CNCF (CNCF's cloud native definition)](https://github.com/cncf/toc/blob/main/DEFINITION.md)
โดยมีข้อยกเว้นเพียงกรณีเดียว คือคำศัพท์พื้นฐานที่จำเป็นต่อการทำความเข้าใจแนวคิด Cloud Native

ด้านล่างนี้คือคู่มือแบบทีละขั้นตอนสำหรับผู้ที่ยังไม่คุ้นเคยกับ GitHub หากคุณเป็นผู้เชี่ยวชาญ GitHub (GitHub Pro) สามารถอ่านคู่มือนี้โดยคร่าว ๆ เพื่อเก็บข้อมูลสำคัญในหัวข้อต่อไปนี้

1. การค้นหาเทมเพลต (Templates) สำหรับการสร้าง Issue หรือคำศัพท์ใหม่
2. การจองสิทธิ์เพื่อจัดการ Issue (Claiming Issues)
3. การแก้ไขข้อผิดพลาดจาก[การตรวจสอบคำผิด](#spell-check)

### การสร้าง Issue ใหม่ {#creating-an-issue}

การสร้าง Issue ใหม่สามารถทำได้โดยไปที่รายการ Issue ใน [Glossary GitHub](https://github.com/cncf/glossary/issues) และเลือก "New issue"

![issues](/images/how-to/howto-01.png)

เลือก "Request to add a new term (English)" จากรายการ templates

![templates](/images/how-to/english-issue-template.jpg)

เพิ่มคำศัพท์ที่ต้องการเสนอ ตอบคำถาม ทำเครื่องหมายในช่องทำเครื่องหมาย และกด "Submit new issue"
หากคุณต้องการเพียงแค่เสนอคำศัพท์ใหม่ ขั้นตอนนี้ถือว่าเสร็จสิ้น
แต่หากต้องการเขียนบทนิยามด้วยตนเอง โปรดอ่านต่อขั้นตอนถัดไปด้านล่างในเอกสารนี้

### การคัดกรอง Issue {#triaging-your-issue}

จากนั้น ผู้ดูแลจะทำการคัดกรอง Issue (triage issue) เพื่อประเมินว่าคำศัพท์ดังกล่าวสมควรถูกเพิ่มเข้าในอภิธานศัพท์หรือไม่ เนื่องจากไม่ใช่ทุกคำศัพท์จะได้รับการอนุมัติ โดยคำศัพท์ที่จะผ่านการคัดกรองจะต้องเป็นแนวคิด Cloud Native ที่ได้รับการยอมรับและใช้งานอย่างแพร่หลาย

โปรดแจ้งให้ผู้ดูแลทราบว่าคุณได้เสนอคำศัพท์ใหม่บน Slack และระบุ (tag) ชื่อบัญชีผู้ใช้งานดังต่อไปนี้ _@iamnoah_, _@nate-double-u_, _@Seokho Son_, _@Jihoon Seo_ และ/หรือ _@Junya Okabe_ เพื่อไม่ให้พวกเขาพลาดการแจ้งเตือน

หากคุณต้องการรับหน้าที่เขียนบทนิยามด้วยตนเอง โปรดแจ้งให้ผู้ดูแลระบบทราบ เพื่อที่พวกเขาจะได้มอบหมายงาน (Assign) ให้กับคุณ

### การส่งคำศัพท์ใหม่ (การสร้าง PR) {#submitting-a-new-term}

ตามที่ระบุไว้ใน [คู่มือรูปแบบเอกสาร](/style-guide/) ของเรา เราแนะนำอย่างยิ่งให้เริ่มต้นด้วย Google Doc หรือ Word

เมื่อคำศัพท์พร้อมส่ง ให้ไปที่โฟลเดอร์ content (ใต้ <>code)

![content](/images/how-to/howto-05.png)

จากนั้นเลือกโฟลเดอร์ "en" (สำหรับภาษาอังกฤษ) หรือสองตัวอักษรแรกของภาษาที่คุณกำลังมีส่วนร่วม

![language folder](/images/how-to/howto-06.png)

จากนั้นเลือก `_TEMPLATE.md`

![template](/images/how-to/howto-07.png)

คัดลอกเนื้อหา

![copy content](/images/how-to/howto-08.png)

และกลับไปที่โฟลเดอร์ "en" คลิก "Add file" และเลือก "Create new file"

![create new file](/images/how-to/howto-09.png)

เพิ่มชื่อคำศัพท์ใน URL ตามที่อธิบายไว้ในส่วน [แนวทางปฏิบัติ](#best-practices)
พร้อมเติมความต้องการนามสกุล .md ไว้ที่ท้ายชื่อ
หากไม่มีนามสกุลนี้คุณจะไม่สามารถกดดูตัวอย่าง (Preview) ไฟล์ได้
จากนั้น วางเนื้อหาจากเทมเพลต (Template Content) ลงในช่องด้านล่าง แล้วคัดลอกบทนิยามของคุณมาใส่ในไฟล์
หากต้องการตรวจสอบว่าคุณใช้ระบบมาร์กดาวน์ (Markdown) ถูกต้องตามที่อธิบายไว้ในส่วน [แนวทางปฏิบัติ](#best-practices) หรือไม่ ให้คลิกที่แท็บ "Preview"

![finalize term](/images/how-to/howto-10.png)

เลื่อนลงมาด้านล่างและตั้งชื่อข้อความ Commit (Commit Message) จากนั้นกด "Commit new file" เมื่อพร้อมส่ง

![commit new file](/images/how-to/howto-11.png)

เมื่อพร้อมที่จะสร้างคำขอรวมโค้ด หรือ Pull Request

![create a pr](/images/how-to/howto-12.png)

กดปุ่ม "Create pull request"
จากนั้น Pull Request ของคุณจะไปปรากฏอยู่ในหน้า "Pull requests"

## การแก้ไขคำศัพท์ที่มีอยู่แล้ว {#update-an-existing-term}

หากต้องการอัปเดตคำศัพท์ที่มีอยู่ คุณสามารถขอการแก้ไขผ่านทางรายการ Issue
หรือทำการแก้ไขและส่ง PR ด้วยตนเอง

### การขอการแก้ไขผ่านทางรายการ Issue {#request-a-change-via-an-issue}

หากคุณพบปัญหาเกี่ยวกับคำศัพท์ใด ๆ สามารถแจ้งเรื่องได้โดยใช้ตัวเลือก "Report issue" บนหน้าเว็บ CNCF Glossary
โดยไปที่หน้าคำศัพท์ของแนวคิดที่คุณต้องการแจ้ง แล้วคลิก "Report issue"
หลังจากนั้น ระบบจะสร้าง Issue ให้คุณโดยอัตโนมัติ

![report issue](/images/how-to/howto-14.png)

อธิบายข้อเสนอแนะของคุณพร้อมระบุเหตุผลที่จำเป็น จากนั้นกด "Submit new issue" เป็นอันเสร็จสิ้นขั้นตอน

![submit issue](/images/how-to/howto-15.png)

### การแก้ไขคำศัพท์โดยตรง {#update-a-term-directly}

หากต้องการแก้ไขคำศัพท์และส่งข้อเสนอแนะ ให้คลิกที่ "Edit this page"

![edit this page](/images/how-to/howto-16.png)

ระบบจะนำคุณไปยังหน้า GitHub ของคำศัพท์นั้น จากนั้นทำการแก้ไขเนื้อหาแล้วสร้างตำชอรวมโค้ด (PR)
โปรดศึกษาข้อมูลในส่วน [แนวทางปฏิบัติ](#best-practices) ด้านบน
และอ่าน [คู่มือรูปแบบการเขียน](/style-guide/) ของเรา เพื่อให้แน่ใจว่าคุณได้ปฏิบัติตามแนวทางที่กำหนดไว้

## การช่วยแปลอภิธานศัพท์เป็นภาษาท้องถิ่น {#help-localize-the-glossary}

หากต้องการช่วยแปลอภิธานศัพท์เป็นภาษาท้องถิ่น โปรดเข้าร่วมช่อง [#glossary-localizations](https://cloud-native.slack.com/archives/C02N2RGFXDF) บน CNCF Slack Workspace แล้วส่งข้อความทักทายพวกเรา
คุณสามารถเข้าร่วมทีมแปลที่มีอยู่แล้ว หรือเริ่มต้นสร้างทีมใหม่ขึ้นมาก็ได้ โดยสามารถศึกษารายละเอียดขั้นตอนได้ที่ [คู่มือการแปลภาษาท้องถิ่น](https://github.com/cncf/glossary/blob/main/LOCALIZATION.md) ของเรา
นอกจากนี้ โปรดอ่านคู่มือ **แนวทางการมีส่วนร่วม (How to contribute)** ของภาษาปลายทางนั้น ๆ เพื่อทำความเข้าใจรายละเอียดเฉพาะในกระบวนการทำงานของแต่ละทีม

## การตรวจสอบคำผิด {#spell-check}

มีสองสาเหตุหลักที่ทำให้การตรวจสอบคำผิด (Spell Check) ไม่ผ่าน:
• มีคำที่สะกดผิดปรากฏอยู่ในการขอรวมโค้ด (PR)
• มีคำศัพท์ใหม่ที่ยังไม่ได้ถูกลงทะเบียนไว้ในรายการคำศัพท์ (Wordlist)

หากต้องการเพิ่มคำศัพท์ใหม่เข้าไปในคลังคำศัพท์ ให้ทำตามขั้นตอนดังต่อไปนี้:

1. ค้นหาไฟล์ wordlist.txt ภายในหน้าการขอรวมโค้ด (PR) ของคุณ
2. คลิก "Edit this file" แล้วเพิ่มคำศัพท์ที่ต้องการลงไป โดยจัดเรียงตามลำดับตัวอักษร
3. ระบุข้อความ Commit (Commit Message) จากนั้นเลือก "Sign off and propose changes"

**หมายเหตุ**: spell check ไม่คำนึงถึงตัวพิมพ์เล็กหรือใหญ่ (case-insensitive)

**คู่มือฉบับนี้ได้รับการอัปเดตโดยอิงตามเทมเพลต (Templates) ของ [The Good Docs Project](https://thegooddocsproject.dev/)**
